# 审计工坊智能分析引擎架构设计思维导图与分析文档

> 本文件由《审计工坊智能分析引擎架构设计思维导图与分析文档.docx》解析整理而来，内容与原文一致，仅调整为 Markdown 格式。
> 文档定位：将原有"七步页面流程"升级为"智能分析引擎工作流"，明确 AI、数据、规则、人工确认和溯源之间的关系。

---

## 一、文档定位

本文档用于定义审计工坊**智能分析模块**的整体架构设计。

核心目标是将原有"**七步页面流程**"升级为"**智能分析引擎工作流**"，明确 **AI、数据、规则、人工确认和溯源** 之间的关系。

原设计主要描述用户看到的页面，但缺少系统内部运行机制，因此需要**从产品流程升级为系统架构设计**。

---

## 二、为什么必须纳入架构设计

**当前七步：**

1. 审计意图分析
2. 方法推荐
3. 法规依据确认
4. 资料准备
5. 数据比对
6. 疑点核实
7. 文书生成

**问题：**

- 只描述页面功能；
- 没有定义 AI 如何获取上下文；
- 没有定义数据来源；
- 没有定义规则关系；
- 没有定义人工确认节点。

例如"方法推荐"不能简单实现为：

```text
项目描述 → LLM → 方法
```

**正确架构应该是：**

```text
项目上下文 → 违规知识库 → 候选违规模型 → 人工确认
    → 审计方法映射 → 数据字段要求 → 分析规则
```

---

## 三、智能分析引擎总体设计原则

1. **AI 不能重新建立项目背景。**
   项目名称、审计对象、范围、事项均来自项目创建流程。

2. **系统状态驱动流程，AI 辅助决策。**

3. **所有 AI 结果必须结构化保存**，包括：
   - 结论
   - 来源
   - 引用
   - 关联对象
   - 数据依据
   - 溯源信息

4. **AI 不能创造审计事实**，只能基于已确认数据进行分析和表达。

---

## 四、AI 上下文管理模型

**禁止：**

```text
完整聊天记录 → LLM
```

**正确：**

```text
project_id
+ project_context
+ audit_items
+ 当前步骤状态
+ 已确认结果
+ 必要溯源引用
```

**输出：** `analysis_task`

**示例：**

```json
{
  "project_id": "A001",
  "audit_item": "采购付款异常分析",
  "target": "供应商付款合规性",
  "scope": "2025年度采购付款"
}
```

## 五、智能分析七步流程架构

### Step1 审计意图确认

**输入：**

- `project_id`
- `project_context`
- `audit_items`

**流程：**

```text
读取项目上下文 → 选择分析事项 → 确认分析目标 → 确认分析边界 → 生成结构化分析任务
```

### Step2 违规模型与审计方法确认

**目标：** 避免 AI 随机生成审计方法。

**流程：**

```text
项目上下文 → 违规知识库 → 候选违规模型 → 人工确认
    → 方法库映射 → 数据字段要求 → 分析规则
```

**核心模型：**

```text
Violation Model
     ↓
Audit Method
     ↓
Data Requirement
     ↓
Analysis Rule
```

### Step3 法规依据确认

**输入：**

- 项目资料
- OCR 内容
- 法规库

**输出：**

- 法规名称
- 条款
- 引用来源

### Step4 资料与数据准备确认

不是简单上传文件，而是**分析准备度检查**：

```text
文件存在 → OCR 完成 → 分类完成 → 结构化完成
    → 进入 data_* 表 → 字段完整 → 存在溯源
```

### Step5 项目数据比对

**审计 AI 不能直接分析 PDF、Word、Excel。**

**正确：**

```text
结构化数据 → 规则计算 → 命中记录 → 证据引用
```

**数据入口：**

- `data_contracts`
- `data_finance`
- `data_registers`

**原始文件只用于查看和复核。**

### Step6 审计疑点人工核实

**模型命中不等于审计疑点成立。**

**流程：**

```text
模型命中 → 疑点候选 → 人工判断 → 确认疑点 → 进入报告
```

**状态：**

| 状态 | 含义 |
|---|---|
| `MODEL_FOUND` | 模型命中，形成疑点候选 |
| `WAIT_CONFIRM` | 等待人工确认 |
| `CONFIRMED` | 人工确认疑点成立 |
| `REJECTED` | 人工判定不成立 |
| `NEED_MORE_EVIDENCE` | 证据不足，需补充 |

### Step7 审计文书生成

**输入：**

- 已确认项目字段
- 确认疑点
- 数据证据
- 法规条款
- 人工意见

**AI 只负责语言组织，不负责事实创造。**

## 六、智能分析控制层

不增加用户页面步骤，通过**后台控制**实现准入。

### 1. 分析入口检查

进入 Step1 前检查：

- 项目完成
- 对象范围完成
- 审计事项完成
- 资料空间存在
- 权限正确

### 2. 数据准备检查

进入 Step5 前检查：

- OCR 完成
- 结构化完成
- 字段存在
- project_id 一致
- trace 存在

### 3. 证据完整性检查

进入 Step7 前检查：

- 疑点已确认
- 数据证据存在
- 文档引用存在
- 法规存在

---

## 七、证据链与溯源体系

智能分析必须形成：

```text
AI 结论
   ↓
审计分析结果
   ↓
数据记录
   ↓
文档引用
   ↓
原始资料
```

任何审计结论都必须能够回溯到：**具体文件、页码、文本块、数据记录**。

---

## 八、最终智能分析闭环

```text
项目上下文
   ↓
违规模型
   ↓
审计方法
   ↓
数据准备
   ↓
数据分析
   ↓
人工核实
   ↓
审计文书
```

**最终目标：**

将审计工坊从"AI 聊天辅助工具"升级为：

> 以**项目状态**为核心、以**结构化数据**为基础、以**规则模型**驱动分析、以**全过程溯源**保障可信度的**智能审计操作系统**。
