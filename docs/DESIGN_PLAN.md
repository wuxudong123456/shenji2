## 人机协作交互模型 — "提交→确认→执行"

### 核心原则

> AI 是审计人员的助手，不是决策者。所有关键节点必须经人工确认后方可进入下一步。

### 三大确认节点

```
① 元数据确认点        ② 表达式确认点         ③ 依据确认点
   │                     │                     │
┌──▼──────────┐    ┌─────▼────────┐    ┌──────▼─────────┐
│ OntoSKU解析  │    │ 违规表达式生成│    │ 法规依据推荐    │
│ 结构化元数据  │    │ (LLM生成/    │    │ (法规关系链)    │
│             │    │  用户手写/    │    │               │
│ AI建议置信度  │    │  自然语言生成)│    │ AI推荐适用层级  │
│ MinerU定位   │    │             │    │               │
│             │    │ 预览匹配结果  │    │ 条款原文预览    │
│ [修改] [确认]│    │ [测试] [确认] │    │ [补充] [确认]   │
└──────┬──────┘    └──────┬───────┘    └──────┬─────────┘
       │                  │                   │
       └──────────────────┼───────────────────┘
                          │
                    ┌─────▼──────┐
                    │  进入分析   │
                    │  自动执行   │
                    └────────────┘
```

### LLM 智能伴随

在每个确认节点，LLM 不是直接决策，而是提供**伴随式分析**：

| 节点 | LLM 伴随内容 |
|------|-------------|
| 元数据确认 | "该字段置信度较低(0.67)，建议人工核对。原始文档第3页已定位。" |
| 表达式确认 | "该表达式将扫描4,810条记录，预计命中约620条(12.9%)。历史同类表达式平均命中率10-15%。" |
| 依据确认 | "该审计对象为市教育局(市级)，建议优先适用省级规定而非仅引用国家法律。已为您标注3条地方性法规。" |

### 溯源锚点

每个输出都携带溯源标识，点击可追溯：

```
[📍 溯源]  ← 通用溯源按钮
  ├─ 数据溯源: 原始文件 → 页面 → 坐标
  ├─ 法规溯源: 条款原文 → 法规全文 → 关系链
  └─ 推理溯源: LLM Prompt → Response → 匹配计算
```

### 一键确认 + 逐条可改

```
┌─────────────────────────────────────────────┐
│ AI 推荐结果 (15条元数据 / 3个违规模型 / 6部法规)  │
│                                             │
│ ✅ 全部已自动勾选                              │
│                                             │
│ [🔄 一键确认全部]  ← 信任AI，全部采纳，进入下一步  │
│                                             │
│ 或逐条查看:                                   │
│ ☑ 补贴金额: ¥350,000  置信度 0.95  [📍溯源]   │
│ ☑ 补贴对象: 张三       置信度 0.87 ⚠️ [📍溯源] │
│    └─ 低置信度提示: 建议人工核对原始文档第3页    │
│ ☑ 发放日期: 2026-03-15 置信度 0.99  [📍溯源]   │
│ ...                                         │
│                                             │
│ ⚠️ 标记项建议逐条确认 (置信度<0.9)              │
│                                             │
│ [✅ 确认选中项]  [🔄 重新分析]                 │
└─────────────────────────────────────────────┘
```

### 确认规则

- **一键确认**: 用户可直接采纳全部AI推荐，一步进入下一步
- **低置信度提示**: 置信度<0.9的项自动标 ⚠️，建议核对但不强制
- **逐条可改**: 任何项可单独取消勾选或修改值
- **可回退**: 确认后仍可返回上一步修改，但需重新确认后续步骤
- **不可跳过**: 必须执行确认操作（一键或逐条），不能直接跳过该节点

- **响应式**: 移动端 3 屏变为垂直滚动单页

## 资料真实性保障 (不可逾越的红线)

审计工作要求每一条结论都有据可查、有源可溯。系统设计遵循**全链路不可篡改 + 可复核**原则。

### 真实性三原则

```
┌──────────────────────────────────────────────────┐
│  Principle 1: 源头锁定                            │
│  所有数据必须有明确的原始来源，不能凭空产生           │
│  → 元数据: OntoSKU提取 + MinerU定位 + 原始文件哈希   │
│  → 法规: sys_core_law原文 + 版本 + 时效性            │
│  → 案例: 语料库Col15原文引用                         │
├──────────────────────────────────────────────────┤
│  Principle 2: 链式溯源                             │
│  任何分析结论必须能逐级回溯到原始资料                  │
│  疑点 → LLM推理过程 → 元数据字段 → 原始文档页面位置    │
│  疑点 → 法规条款原文 → 法规关系链 → 法律层级           │
├──────────────────────────────────────────────────┤
│  Principle 3: 修正留痕                             │
│  用户对元数据的任何修正必须保留历史记录                │
│  AI提取值 vs 人工修正值 vs 最终确认值 — 三者并存       │
└──────────────────────────────────────────────────┘
```

### 数据溯源链 (从疑点回溯到原始资料)

```
审计疑点报告
  │
  ├─ ① 法规溯源 ──────────────────────────────
  │   疑点引用的法规条款
  │   → sys_core_law.content (法规原文全文)
  │   → law_selection_item.clause_analysis (AI条款解析)
  │   → tools_regulation_relation (上位法/相关法/历史版本链)
  │   → potency_level + timeliness (效力+时效校验)
  │
  ├─ ② 数据溯源 ──────────────────────────────
  │   疑点依赖的数据字段
  │   → 人工修正值 (如有)
  │      → OntoSKU AI提取值 (原始)
  │         → MinerU bbox定位 (原始文档坐标)
  │            → 原始上传文件 (SHA256哈希锁定)
  │
  ├─ ③ 推理溯源 ──────────────────────────────
  │   疑点的分析推理过程
  │   → LLM推理日志 (完整prompt + response)
  │   → 违规表达式匹配结果 (语料Col10 SQL逻辑)
  │   → 比对数据来源 (具体字段 → 原始文档)
  │
  └─ ④ 操作溯源 ──────────────────────────────
      所有人工操作记录
      → 谁(who) + 何时(when) + 做了什么(what)
      → 修正前值 → 修正后值
```

### 真实性校验点

| 校验环节 | 校验内容 | 阻断条件 |
|----------|----------|----------|
| **文件上传** | SHA256 哈希锁定，防止文件被替换 | 文件哈希不匹配则拒绝 |
| **元数据确认** | AI提取值 vs 人工修正值 并存对比 | 未逐条确认则无法进入分析 |
| **法规引用** | 自动校验 law_id 存在 + 时效性 | 引用已废止法规时标红警告 |
| **推理输出** | LLM 输出必须标注引用的数据来源 | 无引用来源的结论标"待核实" |
| **报告导出** | 每条疑点附带完整溯源链 | 溯源链不完整的疑点标注"溯源缺失" |

### 四大可视化组件

#### 1. 表达式逻辑树 (左侧面板)

违规表达式 (Col10) 被解析为交互式树形图，每个节点可展开/折叠：

```
         🔴 OR (任一条件满足即违规)
         ├──────────────────────────┐
         │                          │
    🔵 AND (全部条件满足)      🔵 AND (全部条件满足)
    ├──────────────┐         ├──────────────┐
    │              │         │              │
📋 项目名在目录    🏷 收费性质    📋 许可证上     📄 批准文件
  列表中        =经营服务性    收费性质=经营   为空(NULL)
  ✓ 已满足       ✗ 不满足       ✗ 不满足       ✓ 已满足
  (绿色高亮)     (红色闪烁)     (红色闪烁)     (绿色高亮)

结果: 第一条规则 ✗ (2/3不满足)，第二条规则 ✗ (1/2不满足)
     → 🔴 当前记录未命中违规
```

**交互**:
- 鼠标悬停节点 → 显示该条件的字段名、来源表、当前值
- 满足的节点绿色脉冲，不满足的红色闪烁
- 点击节点 → 右侧数据表滚动定位到对应字段

### RegulationAdvisor 特殊设计

```
输入: 审计场景 + 审计对象 (地区/层级/行业)
  ↓
1. 语义匹配: FAISS 检索 law_selection_item (7,101条主法)
  ↓
2. 关系展开: 对每条候选主法，查询:
   - superior (上位法): 国务院→部委→地方 层级链
   - related (相关法): 同层级横向关联
   - history_version (历史版本): 时间维度追溯
  ↓
3. 层级建议: LLM 根据审计对象的行政层级，推荐应适用的法规层级
   (例: 审计市教育局 → 应重点看省级/市级规定，而非仅国家层面)
  ↓
4. 条款匹配: 从 tools_clause_relation 匹配相关的7类条款
  ↓
输出: 法规关系树 + 层级适用建议 + 条款列表
```
