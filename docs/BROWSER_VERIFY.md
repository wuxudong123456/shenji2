# 智能分析 7 步 — 浏览器验证清单

> 前端已由后端同源托管，无需单独启动前端服务。
> 后端运行后，直接浏览器访问即可。

---

## 启动

1. 确认后端在跑：浏览器打开 `http://127.0.0.1:5000/api/health`，应返回 `{"status":"ok"}`
2. 打开智能分析页：`http://127.0.0.1:5000/analysis.html`

## 关键前提：打开浏览器开发者工具（F12）→ Console 标签

整个验证过程**盯着 Console**，任何 `undefined/api/...` 或红色错误都说明请求失败。

---

## 7 步逐项验证

### Step 1 意图解析
- [ ] 左侧文本框输入：`审计某市教育局2026年度教学设备采购是否合规，重点关注化整为零规避公开招标`
- [ ] 点击「AI解析意图」按钮
- [ ] **预期**：右侧结构化字段自动填充（审计领域=行政事业审计、层级=市级、单位=某市教育局）
- [ ] Console 无报错，Network 里 `POST /api/audit/analysis` 返回 200
- [ ] **失败标志**：右侧字段全空 + Console 出现 `undefined/api/...` → 说明 api.js 缓存未刷新（强刷 Ctrl+F5）

### Step 2 违规模型推荐
- [ ] 点击「开始分析」或下一步
- [ ] **预期**：违规卡片列表出现真实模型（如「拆分项目化整为零规避公开招标」），匹配度进度条
- [ ] **预期**：法规推荐出现（招标投标法、实施条例）
- [ ] **预期**：资料推荐出现（采购合同、中标通知书等）
- [ ] Network 里 `POST /api/audit/analysis/{id}/step/2` 或降级走 `/api/audit/knowledge/*` 返回 200

### Step 3 法规依据确认
- [ ] 进入 Step3，法规列表加载（不再空白）
- [ ] 可勾选/取消法规，可添加自定义法规
- [ ] 点击「一键确认全部」

### Step 4 资料上传（关键：验证二次断点 + 真实文件列表）
- [ ] **预期**：进入 Step4，上方「从资料工坊选择」区域显示**从后端拉取的真实文件**（不再是写死的"采购合同汇总.pdf"等假文件）
- [ ] 若项目无文件，显示「本项目暂无已上传资料，请在下方上传新资料」
- [ ] 拖拽一个真实 PDF/图片到上传区
- [ ] **预期**：文件状态从"解析中"变为"已解析"，出现溯源链接
- [ ] Network 里 `POST /api/audit/projects/{id}/upload` 返回 200
- [ ] 点击「确认元数据」

### Step 5 表达式扫描
- [ ] **预期**：漏斗图显示「数据源 N条 → 表达式扫描 → 命中 X条」
- [ ] 若有命中，可点「查看命中记录详情」
- [ ] Network 里 `POST /api/audit/expression/execute` 返回 200
- [ ] **注意**：若数据工坊表无数据，会显示 0 命中——属正常（需先有 OCR 入库数据）

### Step 6 疑点报告
- [ ] **预期**：疑点卡片列表（红色高风险/黄色中风险）
- [ ] 每条疑点显示违规模型 + 法规依据
- [ ] 法规依据显示**真实法规名**（如《招标投标法》），不再是"法规待补充"
- [ ] 可展开「AI推理过程」
- [ ] Network 里 `POST /api/audit/suspicion/generate` 返回 200

---

## 最容易出问题的 3 个点

| 现象 | 原因 | 解决 |
|------|------|------|
| 所有页面数据全空 | 浏览器缓存了旧 api.js | **Ctrl+F5 强制刷新**（清缓存） |
| Console 有 `undefined/api/...` | 同上，旧 JS 没更新 | 强刷，或清浏览器缓存 |
| Network 请求 404 | 后端没启动，或端口不对 | 确认 `http://127.0.0.1:5000/api/health` 可访问 |

## 验证通过的标准

全部满足即联调成功：
- [ ] Step1 真实意图解析（非 mock）
- [ ] Step2 真实违规/法规/资料推荐（非 mock）
- [ ] Step4 显示真实文件列表（非硬编码）+ 可上传
- [ ] Step6 疑点引用真实法规（非"待补充"）
- [ ] 全程 Console 无 `undefined/api/...` 错误
