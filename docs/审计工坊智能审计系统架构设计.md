## 一、系统建设目标

审计工坊目标是建设一个**面向真实审计业务流程**的智能审计系统。

系统不以"聊天式 AI 助手"为核心，而是围绕：

- 审计项目生命周期管理
- 审计资料资产管理
- 数据结构化管理
- AI 智能分析
- 审计证据溯源
- 审计文书生成

形成完整闭环。

**整体目标：**

```text
项目立项 → 审计对象范围确认 → 审计事项确定 → 资料采集
    → 文档智能解析 → 数据结构化 → AI 智能分析 → 疑点发现
    → 审计报告生成 → 项目归档
```

## 三、审计项目生命周期设计

### 1. 审计立项

审计项目创建时，**只填写项目基础信息**。

不应该一次性填写：

- 审计对象
- 审计范围
- 审计事项

**正确流程：**

```text
项目创建 → 填写基础信息 → 进入对象范围确认 → 进入审计事项确认 → 项目正式初始化
```

**原因：**

真实审计业务本身就是逐步明确的：

```text
为什么审计 → 审计谁 → 审计什么 → 怎么审
```

**核心目标：** 管理所有审计原始资料。

## 五、文档智能解析与溯源体系

### 1. 建设目的

解决 **AI 分析结果无法证明来源** 的问题。

**传统方式：**

```text
上传文件 → AI 分析 → 输出结果
```

缺少：**来源、页码、原文、证据链**

**智能审计必须做到：**

```text
AI 结论 → 证据 → 原文 → 文件位置
```

## 六、文档智能解析实现原理

### 第一步：文件上传

用户上传：`采购合同.pdf`

系统生成：**Document 对象**

保存：

- 文件 ID
- 项目 ID
- 文件路径
- 文件类型
- 上传时间

### 第二步：OCR 解析

PDF 进入 OCR。

解析：`第5页 供应商：XX公司 金额：500万元`

同时保存：

- 页码
- 文本
- 坐标
- 可信度

### 第三步：文本切片

将长文档拆分：

```text
Document → Chunk1 → Chunk2 → Chunk3
```

用于：

- AI 检索
- 向量搜索
- 精准引用

### 第四步：信息抽取

例如合同：

- 原文：`合同金额500万元 供应商A公司`
- 转换：`合同金额: 500万元、供应商: A公司`

结构化数据进入数据工坊。

### 第五步：建立溯源关系

**核心：建立 Trace 链。**

例如：AI 发现"采购流程异常"，关联：

```text
AI 结论 → 审计分析结果 → 文本块 → OCR 内容 → PDF第5页 → 原始文件
```

用户点击：**查看原文**。

## 七、文档解析体系所属模块设计

文档智能解析**不应该独立成业务模块**。

**推荐归属：**

```text
资料工坊
├── 文件管理
├── 文档智能解析中心
│   ├── OCR 服务
│   ├── 文本切片服务
│   ├── 信息抽取服务
│   └── 溯源服务
└── 权限管理
```

## 八、数据工坊设计

- **资料工坊** 负责：非结构化资料
- **数据工坊** 负责：结构化数据

**流程：**

```text
资料上传 → OCR 解析 → 信息抽取 → 结构化表 → 智能分析调用
```

## 九、AI 智能分析设计

### AI 上下文原则

**不要：**

```text
完整聊天记录 → LLM
```

**应该：**

```text
项目状态 + 步骤结果 + 确认数据 + 溯源引用 → LLM
```

## 十、AI 伴随优化设计

### 原规则问题

大量：

- 点击消息
- 状态消息
- 临时反馈

导致：**上下文污染**。

### 新规则

**步骤内操作** — 只更新状态：

```text
勾选 / 取消 / 拖拽 / 切换 → 状态变化
```

不进入聊天。

**步骤完成** — 生成固定总结。

例如：

> 第二步"方法推荐"已完成：已确认 2 个违规模型，关联 3 项审计方法，4 项资料要求，2 部法规。下一步进入法规依据确认。

---

## 十一、AI 推荐能力设计

### 方法推荐

**输入：** 项目基本信息

例如：

- 审计类型：采购
- 审计对象：供应商管理

**输出：** 违规类型

- 供应商准入违规
- 采购流程违规
- 关联交易风险

### 法规依据推荐

**依据：**

- 项目基本信息
- 资料工坊资料
- 法规库

**输出：**

- 法规名称
- 条款
- 适用原因
- 引用来源

**必须支持：全文溯源。**

## 十二、最终系统闭环

```text
审计项目 → 资料工坊 → 文档智能解析 → 数据工坊 → 知识库
    → AI 智能分析 → 疑点发现 → 审计文书 → 项目归档
```

---

## 十三、核心建设原则

### 原则一

**AI 不能替代流程。**

应该：系统状态驱动流程，AI 辅助决策。

### 原则二

**所有 AI 结果必须结构化。**

包含：

- 结论
- 来源
- 引用
- 置信度
- 关联对象

### 原则三

**溯源能力必须提前建设。**

因为：法规推荐、疑点分析、报告生成**全部依赖统一溯源体系**。

---

## 最终定位

审计工坊**不是一个聊天机器人**，而应该建设成为：

> 一个以**审计项目**为核心，以**资料资产**为基础，以**数据工坊**为支撑，以 **AI 智能分析**为能力，以**全过程溯源**为保障的**智能审计操作系统**。

```text
项目管理 → 资料资产 → 数据资产 → 知识资产 → AI 能力 → 审计成果
```
