# 政府采购综合审计案例包设计规格

## 1. 目标

为审计实务工坊制作一套可重复使用的虚拟政府采购审计案例资料，用于验证以下完整业务链路：

> 创建审计项目 → 输入审计意图 → 匹配违规模型与法规 → 人工确认 → 上传原始资料 → OCR → 模板分类与字段提取 → 数据工坊核验 → 违规表达式扫描 → 生成疑点及审计文书。

案例全部使用虚构单位、人员、账号、编号和金额，不包含真实个人信息或涉密数据。资料中的业务事实、文件间勾稽关系和预期结果必须确定且可复算。

## 2. 适配边界

### 2.1 以当前实现为准

- 项目通过 `POST /api/audit/projects` 创建，字段使用 `name`、`description`、`audit_period`。
- 文件通过 `POST /api/audit/projects/{project_id}/upload` 上传，表单字段名为 `file`。
- 原始文件进入项目独立 MinIO Bucket，路径由现有后端生成。
- OCR 结果和原始文件位置落入 `audit_document_traces`。
- 模板名称严格采用 `audit/<类别>/<文档类型>` 形式，并优先使用现有通用模板。
- 结构化基准覆盖现有六张数据表：`data_contracts`、`data_finance`、`data_legal_docs`、`data_registers`、`data_credentials`、`data_general`。
- 违规扫描使用当前表达式解析器已支持的比较、`AND`、`OR`、`IN`、`LIKE` 和 `BETWEEN` 语法。
- 疑点成果结构对齐 `project_suspicions` 的 `suspicion_items` 与 `evidence_chain`。

### 2.2 当前能力限制

当前上传路由已完成 MinIO 入库和 OCR 调用，但上传后自动完成模板匹配、字段提取并写入六张数据表的链路仍可能受 OCR、LLM 和运行时服务状态影响。因此资料包同时提供：

1. 可直接上传的原始材料，用于真实链路测试；
2. 同内容的结构化“金标准”，用于服务不可用时校验下游表达式、疑点和文书环节；
3. 逐环节验收记录，用于区分上传、OCR、分类、提取、入库或规则执行故障。

本资料包不修改现有业务代码，不伪装尚未实现的自动化能力。

## 3. 案例设定

### 3.1 项目基本信息

| 项目字段 | 设计值 |
|---|---|
| 项目名称 | 东河县教育局 2025 年度政府采购专项审计 |
| 被审计单位 | 东河县教育局（虚构） |
| 审计期间 | 2025-01-01 至 2025-12-31 |
| 审计对象 | 信息化设备、办公家具及运维服务采购活动 |
| 审计目标 | 检查采购方式、拆分采购、保证金、合同履行、验收、发票与付款合规性 |
| 审计基准日 | 2026-01-31 |

### 3.2 样本构成

案例包含三组采购业务：

- A 组正常样本：公开招标采购教学终端，手续完整、金额勾稽一致。
- B 组核心异常：同一预算项目在短期内拆分为三份办公家具合同，供应商存在关联特征，用于识别拆分采购疑点。
- C 组复合异常：运维服务合同履约保证金超过合同金额 10%，并存在验收日期早于服务完成、发票金额与付款金额不一致的问题。

材料中设置少量非关键字段缺失和低质量扫描页，用于验证“未提供”、人工确认和溯源能力；金标准不会把缺失字段补写成事实。

## 5. 原始材料设计

### 5.1 文件格式

- PDF：作为主要上传与 OCR 测试文件，保留稳定页码。
- DOCX：提供可编辑的业务文书源文件。
- XLSX：提供采购台账、保证金台账和支付明细，保留可计算字段。
- CSV/JSON：仅作为机器可读基准，不替代原始业务资料。

### 5.2 材料清单

| 业务组 | 资料 | 主要模板/落表 |
|---|---|---|
| 共用 | 项目立项书、审计通知信息、采购管理制度摘要 | `audit/规章制度类/*` 或 `data_legal_docs`/`data_general` |
| A 正常 | 采购申请、预算批复、招标文件、中标通知书、合同、验收单、发票、凭证、付款回单 | 合同、业务单据、财务票据、财务凭证 |
| B 拆分 | 同源采购申请、三份询价记录、三份合同、三张发票、三笔付款、汇总台账 | `data_contracts`、`data_finance`、`data_registers` |
| C 复合异常 | 采购审批、服务合同、履约保证金收据/台账、阶段验收单、发票、凭证、回单 | 六张表中的合同、财务、台账、单据类表 |

每份材料必须含唯一业务编号，并能通过采购项目编号、合同编号、供应商、金额和日期与其他材料关联。

## 6. 结构化金标准

### 6.1 工作簿

生成一个 `结构化提取金标准.xlsx`，至少包含以下工作表：

- `项目与文件清单`
- `data_contracts`
- `data_finance`
- `data_legal_docs`
- `data_registers`
- `data_credentials`
- `data_general`
- `字段勾稽`
- `预期疑点`

工作表列名与数据库核心列保持一致；模板特有字段统一存放在可读的 `extra_fields` JSON 文本列中。金额、日期和比例使用真正的数值/日期类型，不写成带单位的文本。

### 6.2 基准 JSON/CSV

- 每张数据表提供 UTF-8 CSV。
- 提供合并的 `golden_dataset.json`，包含项目、文件、模板、字段、规则、命中结果和证据链。
- `document_trace_id` 在基准文件中使用稳定的逻辑标识，如 `TRACE-B-CONTRACT-01`；实际上传后通过文件名与真实数据库 ID 对照。

## 7. 违规规则与标准答案

### 7.1 规则集合

| 编码 | 规则 | 预期 |
|---|---|---|
| GP-001 | 同一预算项目、相近时间、同类标的多份合同金额汇总超过阈值 | B 组命中 1 个汇总疑点 |
| GP-002 | 履约保证金金额 / 合同金额 > 0.10 | C 组命中 1 条 |
| GP-003 | 验收日期早于合同约定服务完成日期，且无提前验收依据 | C 组命中 1 条 |
| GP-004 | 发票金额、记账金额、实际付款金额不一致 | C 组命中 1 条 |
| GP-005 | 合同、发票、付款金额一致且验收正常 | A 组不命中，用作阴性样本 |

GP-001 涉及跨行汇总，若当前逐行表达式引擎不能直接聚合，则采用“采购汇总台账”中的预计算汇总字段执行；操作手册需明确这是当前引擎边界，而不是把聚合能力虚构为已实现。

### 7.2 命中判定

每条规则记录：输入表、表达式、预期扫描行数、预期命中行、预期不命中行、关键字段、证据文件和人工复核说明。验收时同时统计：

- 真阳性：4 个核心疑点；
- 真阴性：A 组全部记录及 B/C 组未违反对应规则的记录；
- 漏报：应命中但未命中；
- 误报：不应命中但命中。

## 8. 审计输入与人工确认

提供可直接粘贴的审计意图：

> 对东河县教育局 2025 年度政府采购活动开展专项审计，重点检查是否通过拆分采购规避公开招标，是否超比例收取履约保证金，以及采购合同、验收、发票、记账凭证和银行付款之间是否一致。

同时给出意图分析预期、候选违规模型关键词、建议资料清单、法规检索关键词和人工确认表。法规只提供检索目标和核验字段，不硬编码数据库中未经查询确认的 `law_id`。

## 9. 预期成果

生成以下示范成果：

- 疑点清单；
- 证据链索引；
- 审计取证单；
- 审计工作底稿；
- 审计疑点报告；
- 审理复核意见表。

疑点表述区分“系统识别的疑点”和“经审计人员核实后的定性”。未取得充分证据前，不把疑点直接表述为已确认违法事实。

## 10. 操作手册

操作手册按当前前端页面和实际 API 编排：

1. 在项目管理创建项目；
2. 在智能分析输入审计意图；
3. 检查违规、资料和法规推荐；
4. 完成人工确认断点；
5. 在资料工坊按清单上传 PDF/XLSX/DOCX；
6. 查看文件状态与 OCR 结果；
7. 核对模板匹配及结构化字段；
8. 在数据工坊与金标准逐表比对；
9. 执行违规表达式并记录命中；
10. 生成疑点、查看溯源并输出审计文书；
11. 填写验收记录。

每一步均列出前置条件、输入、页面/API、预期响应、失败表现和排查位置。

## 11. 验收标准

### 11.1 文件质量

- 所有文件可正常打开，无损坏、乱码和页面裁切。
- PDF 页码稳定，关键字段肉眼可辨。
- DOCX 和 XLSX 经渲染检查，无明显布局或公式错误。
- `manifest.json` 中的文件数、SHA-256、业务组、模板建议和预期落表完整。

### 11.2 业务一致性

- 同一业务在申请、合同、验收、发票、凭证和回单之间可勾稽。
- A 组无预设违规；B/C 组异常均有至少两份独立材料支撑。
- 结构化金标准的金额汇总与原始资料完全一致。
- 疑点报告中的每个事实均能定位到具体文件和页码/表格行。

### 11.3 系统适配

- 项目创建和文件上传符合现有接口字段。
- 模板建议均能在 `backend/templates/profiles/audit/` 中找到或明确使用类别通用模板。
- 六类结构化数据均符合当前数据库表结构。
- 表达式不使用解析器未声明支持的语法；跨行规则使用预计算汇总字段。
- 验收记录能明确区分 OCR、分类、提取、入库、表达式和生成环节的结果。

## 12. 非目标

- 不连接或修改真实生产数据库内容。
- 不创建真实印章、真实签名、真实身份证号或真实银行账户。
- 不修改审计工坊现有前后端实现。
- 不把虚拟法规编号冒充数据库真实记录。
- 不以本案例替代真实审计人员的定性和复核责任。

## 13. 实施顺序

1. 建立目录、编号体系、业务事实表和文件清单；
2. 制作三组原始业务资料；
3. 生成结构化金标准与规则标准答案；
4. 生成预期审计成果；
5. 编写操作手册与验收表；
6. 计算清单哈希并执行内容、公式和视觉检查。
